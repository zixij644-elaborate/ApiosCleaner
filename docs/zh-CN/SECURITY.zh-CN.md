# 安全策略

## 报告漏洞

**不要**为安全漏洞开公开 issue。请通过 GitHub 的 Security Advisory 功能私下报告：

1. 进入仓库的 **Security** 标签页。
2. 点击 **Report a vulnerability**。
3. 描述问题：受影响的命令或代码路径、最小复现（攻击者触发需要什么条件）、影响。

报告会尽快确认，修复就绪后以安全版本发布。

## 范围

本项目是一个应用清理工具：其核心会删除和移动文件，因此路径处理中的缺陷具有真实的破坏潜力。尤其关注：

- 绕过关键路径保护（`trash.rs::validate_path`），使受保护的系统路径可被删除
- 路径归一化/穿越问题，使构造的路径逃出预期范围
- 绕过确认流程（未经用户同意的破坏性操作）
- 孤儿检测将活应用误判为可删除

## 支持的版本

| 版本 | 支持 |
|---|---|
| 最新发布版（v0.2.x） | ✅ |
| 更早的发布版 | ❌ |

只有最新发布版接收安全修复。
